## Implementation Instructions

1. Implement `runtime.hpp` defining the `Runtime` coordinator. It manages worker thread registration, operator assignment, metrics reporter startup, and clean pipeline shutdown.
2. Address **INV-001 (Termination Event-Count Matching)**: In the coordinator/harness architecture, standard queue-drain checks must be supplemented or replaced by exact event-count matching. The `Runtime` class or the harness using it must wait until the exact count of events emitted by the source matches the count of events written/processed by the sink before initiating the stop sequence.
3. Define the interface so the coordinator can register operators, map worker IDs, override CoreAffinity settings, and access the MetricsReporter instance.
4. Implement `revised_software/source/CMakeLists.txt` to configure:
   - Target standard C++17.
   - Core include path `include` as interface target library (`klstream`).
   - Compiler warning flags (`-Wall -Wextra -Wpedantic -O2`).
   - Threading flags (`Threads::Threads`).

## Invariant Checklist

- **INV-001:** Termination Event-Count Matching. Checked by comparing count of processed events at source and sink.
- **INV-003:** Fresh compile verification. Checked by building CMake target.
- **INV-004:** Configuration parameters must be identical across build pipelines. Checked by testing harness configuration defaults.

---

## Predicted Failure Modes

- **Silent Event Loss under CPU Spikes:** Polling loop terminators can shut down pipelines prematurely if queues look empty but events are still in thread buffers. Exact matching prevents this.
- **Join Deadlocks:** If a worker thread hangs or is blocked on a full queue during stop, `std::thread::join()` will hang. Ensure non-blocking queue options or atomic status indicators are accessible.
