# AMOS migrated-tree re-audit and repair record

1 October 2026, Asia/Kathmandu. **The migrated foundation was not free of defects. Concrete mathematical, diagnostic and factory-integrity problems were found and repaired. The current project remains an incomplete research system with no admitted results.** Passing the checks recorded here does not establish that every possible scientific or implementation error has been eliminated.

The human authorized scrutiny and repair of the new folder and supplied `BPfeat.md` as context with an explicit instruction not to trust it blindly. This record follows `AGENTS.md`, the governing plan and the local repair contract. The contract received same-session source review. An independent human or fresh-session scientific review is still required before scientific claims are admitted. No legacy runner or research certification was executed for this repair.

## Scope, file coverage and evidence boundaries

The audit read the active native source, label/math references, engine tests, diagnostic replay, active factory execution, validation, inference, signing, snapshot and bundle paths, their tests and governing documents. It traced the actual callers as well as helper functions: a signature helper existing in a module does not mean an audit verifies signatures. Historical reports and archived factory code are retained as historical material. Their hashes and text inventories do not revalidate their measurements or make them current runtime dependencies.

`current_tree_inventory.json` records a full byte hash and physical line count for each Git-visible file included in the final scan, including new files. `current_tree_scan.json` records syntax/strict-JSON checks and whole-text pattern counts; these are coverage tools, not semantic verdicts. Build products, Git internals, ignored raw data, private state/keys and bulk run outputs are excluded from that current source scan. Raw candidates already have separate full profiles/hashes from migration and remain unverified quarantine. `validation.json` binds actual native executable hashes, build flags, commands, tool versions, logs and the supplied document's identity. These artifacts describe an audit snapshot, not a prospective experiment or an authenticity certificate.

Manual semantic review concentrated on scientific operators, source identity/time rules, feedback availability, success/failure paths and the actual admission checks. Sanitizers and fixture replay supply additional counterexamples. No formal concurrency proof, provider authentication, sensor validation, independent third-party reproduction or exhaustive proof over all inputs was performed. The user requested every line be scrutinized; line inventories, source review and targeted execution make the coverage inspectable without claiming a universal proof. Future contracts must repeat this discipline for new paths.

The existing `docs/audit/migration_manifest.json`, original environment observations and original logs are preserved as dated historical snapshots. Their old source hashes and 18/276 test counts describe the earlier foundation, not the repaired tree. The current record supersedes their current-status interpretation without changing their original bytes.

## Compatibility and factory trust boundary

The supplied version is 3.3.0. The active local patch is **3.3.1-amos.1**, recorded in VERSION, bootstrap manifest, changelog and planning state. Existing v3 plan declarations remain accepted; the empty AMOS template is intentionally not upgraded into a real protocol. Native diagnostic receipt v3 and the batch trace are new interfaces. The first 21 prediction columns retain their positions, with identity/clock fields appended; future consumers must use versioned schemas rather than relying on position. Native failure artifacts are not completed research receipts.

The repair preserves positive binary-profile behavior while correcting false assurance assertions and replacing inadequate attack fixtures with stronger actual-path tests. Historical changelog/spec claims describe their supplied version and are not evidence that the claimed property existed. The local README and this amendment govern current capability disclosures. Snapshot roots are also independently recomputed on the actual frozen-input audit path. Original hashes/logs remain inspectable in repository history. The snapshot algorithm change invalidates an unreviewed attempt to replay earlier roots using the new algorithm; use original versioned verification or freeze a new prospective epoch.

Ed25519 requires the actual installed cryptography library. The standard-library fallback is HMAC; its verification bytes are shared secret material despite the historical `.pub` filename. They cannot be released as public verification material. Same-user workers may access or alter local keys/state. Resource limits are enforcement requests where supported, not measurements; disabled-network declarations are not sandbox proof. The index detects missing attempts against retained local state, but cannot defeat a user rewriting all state. Local assurance is therefore deliberately narrow. Native/streaming/isolated adapters, genuine reviewer decisions and independent reproduction remain AMOS-10/11/16/18 work.

## Supplied report and research decision

The supplied report is preserved verbatim and critically assessed in `docs/research/deep_research_review.md`. It contains valid cautions and substantive mistakes. Its elapsed-time EMA fails constant-signal normalization; it misidentifies RALF as static, misdates ADWIN, overstates Clipper's numerical guarantee, insufficiently purges label windows, confuses last activity with observation end, and proposes coverage/resource matching that can hide policy losses. Its AUC floor and example equivalence margin are not scientific acceptance criteria. Its citations/permissions/venues are not adopted without verification.

The recommended path is conditional: choose an actual feature-publication/query study only if a pilot on admitted training/validation data demonstrates a real cost-changing mechanism. Otherwise publish an honestly scoped batching/control analysis if it produces meaningful new insight, or stop/pivot. Changing gain in a constant-cost per-event EMA cannot establish saved compute. A controller decreasing B under pressure may increase fixed overhead or harm latency; implementer compliance with that sign is not evidence the sign is correct for the plant. Preserve opposing outcomes.
